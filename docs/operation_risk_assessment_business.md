# 【ビジネス向け】競馬データ処理システム 運用開始時のエラー・障害リスク

本ドキュメントは、システムの裏側（GCPやプログラムなど）の専門知識がない方でも分かりやすいように、運用開始後に起こり得る主なエラートラブルとその影響を整理したものです。

## 1. データの「中身」に関するトラブル

* **アップロードされたファイルが壊れている・形が違う**
  担当の方がファイルをアップロードする際、ZIPが壊れていたり、通常と全く違う形（フォーマット）のデータが入っていたりすると、システムがデータを読み込めず、その後の処理がすべて止まってしまいます。

* **想定外の「空欄」や「おかしな文字」が入ってくる**
  元データの中にシステムが想定していない「空欄」や特殊な文字が混ざっていた場合、システムが計算エラーを起こして処理が止まってしまうことがあります。（過去に発生した調教データの表示エラー等と同じ種類のトラブルです）。

## 2. データの「遅れ」に関するトラブル

* **大元のデータ配信の遅れによる「オッズが古いまま」問題**
  システム自体は1日5回（6時、9時、12時、15時、18時）正確にオッズを更新しにいきますが、そもそものデータの大元（JRAやKOL側）からのデータ提供自体が遅れた場合、システムはエラーを出さずに「今の時点である一番新しいデータ（＝古いデータ）」を出力してしまうため、画面上のオッズが更新されないという事態が起こります。

## 3. システムが「パンク」するトラブル

* **週末などデータが多すぎる日の「メモリ不足・時間切れ」**
  出走馬が多い週末などで極端にデータ量が増えた場合、システムを動かしているクラウド上の「作業デスク（メモリ）」がいっぱいになったり、決められた制限時間（30分）以内に計算が終わらなくなったりして、処理が途中で強制終了（パンク）してしまう恐れがあります。
  （※ただし、これまでの検証・テスト運用期間中でこの現象が発生したことは一度もないため、実際に起こる確率はかなり低いと考えられます。）

* **1つのエラーが全体を巻き込むドミノ倒し（直列処理の影響）**
  現在、「スケジュール出力 → レース出力 → レース・馬詳細出力 → オッズ出力」という4つの作業を順番に（1列で）行う設定になっています。そのため、もし最初の作業でエラーが起きると、後の作業もすべて巻き添えになって止まってしまい、全くデータが出力されなくなってしまいます。
  （※注意：これは「システム上のデータが消えてしまう」という意味ではありません。単に「新しいデータが外部に出力・更新されないままになる」状態にとどまります。）

## 4. 外部システムとの「連携・通信」トラブル

* **ファイルの転送先（FTPサーバー）への接続失敗**
  出力したCSVファイルを「ファイル置き場（FTPサーバー）」へ送ろうとした際、送り先のサーバーがダウン・メンテナンス中であったり、何らかの理由でパスワードが変わってログインできなかったりすると、データの転送が失敗します。

* **画面側（Bubble）への通知失敗や「送りすぎ」制限**
  「データを出力しました」という通知を画面側のシステム（Bubble）に送る際、同時に大量の通知を送りすぎるとBubble側で「制限」にかかってしまい、通知が届かなくなることがあります。また、Bubbleシステムと繋ぐための「秘密の合鍵（APIキー）」の有効期限が切れた場合も通知ができなくなります。
