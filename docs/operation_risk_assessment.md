# KOL競馬データ処理・変換パイプライン 運用開始時のエラー・障害リスク評価

本ドキュメントでは、KOL競馬データ処理・変換パイプラインの運用開始時に想定される主なエラーや障害リスクをリスト化し、整理しています。

## 1. 入力データフォーマット・仕様変更のリスク
* **アップロードファイルの異常**
  ユーザーからGCSにアップロードされるファイル（ZIP等）が破損している、または想定外のフォーマットである場合、後続のBigQueryへのロード処理やデータ変換が失敗するリスクがあります。
* **予期せぬNULLや空白値による変換エラー**
  連携元データ（`kol_keiba.*`）に想定外のフォーマットが入ってきた際、`race_uma`などの複雑なSQL（結合やCASE式）処理において、型不一致や計算エラーが発生するリスクがあります（過去の`chokyo_den_*`周辺でのバグの再発など）。

## 2. 外部連携タイミング・遅延のリスク
* **オッズ更新の遅延（スケジュール実行）**
  Cloud Schedulerを用いて定時更新（6, 9, 12, 15, 20時）を設定していますが、データの源泉であるJRAやKOLからの提供自体が遅れた場合、システム上のパイプラインは正常に動作しても、エクスポートされるオッズデータが古いままになってしまうリスクがあります。

## 3. クラウドアーキテクチャ・リソースの制限リスク
* **直列実行による単一障害点（SPOF）**
  Cloud Workflows（`dataform-trigger-workflow`）の定義上、各Cloud Functionsのエクスポート処理（Schedule -> Races -> Details -> Odds）が **直列（直列呼び出し）** で定義されています。仮に最初の `ExportSchedule` 処理でエラーが発生した場合、そこでワークフロー全体が異常終了し、後続のファイルが一切処理されない可能性があります。
* **Cloud Functionsのメモリ不足 (OOM)・タイムアウト**
  `export_race_uma_details` などの関数では、更新レコードの判定や辞書作成処理をPythonのメモリ上で行っています。更新件数が極端に多い日（週末の本番稼働時などデータ増大時）に、Cloud Functionsのメモリ上限（現在8GB）を突破してクラッシュするか、関数のタイムアウト設定（1800秒）を超過して処理が強制終了するリスクがあります。

## 4. 外部システム連携（FTP / Bubble API）のリスク
* **FTPサーバーの障害・接続拒否**
  エクスポート先のFTPサーバー（`smartkb.mixh.jp`）のダウン、メンテナンス、あるいはIPアクセス制限や認証情報（Secret Managerに格納されたパスワード）の変更等により、CSVファイルのアップロードが失敗するリスクがあります。
* **Bubble APIのレート制限（Rate Limits）と認証エラー**
  Bubble APIに対して短時間で大量のリクエストを送信した際、Bubble側のAPI制限に抵触してHTTP 429等のエラーが返却されるリスクがあります。また、APIキー（`kol_bubble_workflow_api_key`）の不意な変更や期限切れにより、HTTP 401/403エラーが発生し通知が届かなくなるリスクがあります。
